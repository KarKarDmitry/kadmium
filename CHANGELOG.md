# Changelog

## Unreleased

### Breaking

**`int8` больше не округляется молча** (`9927d3a`, `244e4a7`).

Адаптер приводил `int8` в `number` парсером на уровне пула, поэтому любое
значение выше `Number.MAX_SAFE_INTEGER` (2^53 − 1) округлялось до соседнего и
было неотличимо от корректного числа. Внешние идентификаторы шире 2^53 —
Discord- и Twitter-снежинки, Terabase-ключи — читались как мусор.

Теперь `int8` и `numeric` приходят строкой, а ORM приводит их к `number`
точно либо **бросает ошибку с именем модели и колонки**. Молчаливого
искажения больше нет.

Что изменилось для пользователя:

- `int8`/`numeric` читаются как `number`, как и обещает `~shape` — раньше
  `numeric` приходил строкой вопреки типу, а `int8` округлялся.
- Значение вне `2^53` **падает** с ошибкой вместо округления. Для таких
  идентификаторов нужен `f.pk.uuid` / `f.pk.string`; чтение их как `bigint`
  больше невозможно намеренно.
- `orm.raw()` отдаёт `int8` **строкой**. Объявить `raw<{ id: number }>` было
  ложью: без IR-поля ORM не знает, что это не текст. В проекциях, где колонка
  известна, тип объявляется явно:

  ```typescript
  orm.select(User)
    .fields(() => [sql`count(*)`.as('cnt').tsType()])
    .go(); // cnt: number
  ```

- `sql`-фрагменты в `fields()` без `.tsType()` приходят ровно так, как их
  прислала база.

Точные правила выбора приведения — в `packages/core/AGENTS.md`
(раздел «Приведение int8/numeric при чтении»); какие oid парсятся — в
`packages/sql-pg/AGENTS.md`.
